# 🎄 Krampus — веб-клиент

[![Node.js](https://img.shields.io/badge/Node.js-20+-green)](https://nodejs.org/)
[![Go](https://img.shields.io/badge/Go-1.21+-blue)](https://golang.org/)

**Krampus (front)** — клиентская часть учебного мессенджера на **Nuxt 3 (Vue 3, TypeScript)**. Обеспечивает текстовый чат в реальном времени, групповые чаты с каналами, аватары пользователей и групп, а также голосовые и видеозвонки по технологии **WebRTC**.

Клиент работает в связке с Go-бэкендом (REST + WebSocket + SSE) и отдельным Go-сервером сигналинга звонков.

> ⚠️ Статус: **учебный прототип / активная разработка**. Основной функционал (обмен сообщениями и установка WebRTC-соединения) реализован и работает.

---

## ✨ Возможности

- 📝 Текстовые сообщения в реальном времени (WebSocket)
- 👥 Личные и групповые чаты, каналы внутри группы
- 🖼️ Аватары пользователей и групп
- 🎥 Голосовые и видеозвонки peer-to-peer (WebRTC)
- 🔍 Поиск по сообщениям и пользователям
- 🧭 Боковые панели навигации (чаты, участники, настройки)
- 🔧 Модульная архитектура на Pinia (stores) и композаблах

## 🚀 Запуск

Есть два способа: через общий Docker Compose (рекомендуется) или вручную.

### Вариант A. Через Docker Compose (рекомендуется)

Весь стек (бэкенд, клиент, сервер сигналинга, базы данных) поднимается из корня проекта одной командой:

```bash
cd ..                          # перейти в корень репозитория Krampus
cp .env.example .env           # только при первом запуске
docker compose up -d --build
```

После запуска:

| Адрес | Назначение |
|---|---|
| http://localhost:3000 | Веб-клиент (этот проект) |
| http://localhost:8080 | Бэкенд (REST + WebSocket + SSE) |
| ws://localhost:8090 | Сервер сигналинга звонков |

Подробный тестовый сценарий — в [README.md в корне проекта](../README.md).

### Вариант B. Запуск вручную

#### Требования

- [Node.js](https://nodejs.org/) 20+
- [Go](https://golang.org/) 1.21+
- Запущенный бэкенд Krampus (`go run ./cmd/app` из корня) и инфраструктура (Postgres, Redis, Kafka)

#### 1. Сначала запустить сервер сигналинга звонков

> Сервер сигналинга нужно запускать **первым**, чтобы избежать ошибок инициализации звонков.

```bash
cd server/api
go run main.go
# Сервер слушает ws://localhost:8090/ws/:idRoom/:typeWS
```

#### 2. Установить зависимости клиента

```bash
cd front
npm install
```

#### 3. Запустить клиент в режиме разработки

```bash
npm run dev
# Клиент доступен по адресу http://localhost:3000
```

## ⚙️ Переменные окружения клиента

Адреса бэкенда задаются переменными (потребляются браузером, поэтому указывают на `localhost`):

| Переменная | Значение по умолчанию | Назначение |
|---|---|---|
| `NUXT_PUBLIC_API_BASE` | `http://localhost:8080/api/v1` | Базовый адрес REST API |
| `NUXT_PUBLIC_WS_BASE` | `ws://localhost:8080` | Базовый адрес WebSocket |

## 🧪 Проверка

1. Открыть http://localhost:3000 и зарегистрировать пользователя.
2. Открыть второе окно в **режиме инкогнито** и зарегистрировать второго пользователя (авторизация хранится в `localStorage`).
3. Создать группу, канал, обменяться сообщениями — они приходят в реальном времени.
4. Для проверки звонков **разрешить доступ к микрофону** в обоих окнах и зайти в голосовой канал с двух аккаунтов.

Подробности по звонкам и их отладке — в [CALL.md](CALL.md).
