# 💬 Krampus — мессенджер для учебной организации

Проект разработан как дипломная работа по специальности **09.02.07 Информационные системы и программирование**.

Krampus — это полнофункциональный мессенджер реального времени: бэкенд на **Go** и веб-клиент на **Nuxt 3**, со звонками через **WebRTC**, поиском и так далее. Весь стек поднимается одной командой `docker compose up`.

---

## 📌 Статус проекта

Проект является учебным прототипом и предназначен для демонстрации основного процесса обмена сообщениями в реальном времени и проведения групповых звонков.

В дальнейшем систему можно расширить:

- подключением Cassandra и MongoDB (уже присутствуют в `docker-compose.yml`, но не задействованы в коде);
- полноценной медиа-инфраструктурой (загрузка и раздача файлов);
- SFU/MCU-топологией звонков для большего числа участников;
- автоматическими тестами;
- расширенной аналитикой и модерацией.

## 📌 Назначение проекта

Приложение предназначено для учебной организации и заменяет заблокированные или недоступные мессенджеры для студентов и преподавателей. Основные возможности проекта:

- создавать аккаунты через регистрацию и авторизацию;
- студентам и преподавателям обмениваться сообщениями в реальном времени;
- создавать личные и групповые чаты, а также каналы внутри групп;
- проводить групповые голосовые и видеозвонки (WebRTC);
- хранить переписку и пользовательские данные в единой базе данных;
- полнотекстовый поиск сообщений;
- аватары пользователей и чатов (хранятся в базе как data URL).

## ⚙️ Архитектура

Внутренние модули следуют единой слоистой структуре:

```text
internal/<module>/
  domain/     — сущности, интерфейсы
  service/    — бизнес-логика
  storage/    — адаптеры БД / кэша
  adapters/   — HTTP-обработчики, WebSocket, SSE
```

Транспортный слой:

- **REST API** через Gin по адресу `/api/v1` (маршруты авторизации — без аутентификации, маршруты чатов — за `AuthMiddleware`);
- **WebSocket** по адресу `/ws` — рассылка через потребителя Kafka;
- **SSE** по адресу `/sse` — односторонний поток на комнату с дозагрузкой пропусков по `Last-Event-ID`.

Путь прохождения сообщения:

1. Клиент отправляет сообщение по WebSocket.
2. `MessageService` пишет в Postgres через sqlc и публикует в Kafka (топик `incoming`).
3. Потребитель Kafka рассыпает сообщение подписчикам (индексатор поиска, аудит, WebSocket-рассыльщик).

## 🚀 Запуск приложения локально

В этом разделе подробно, шаг за шагом, описано как поднять **весь** стек (бэкенд + фронтенд + инфраструктура) тремя способами. Если не уверены — используйте **Способ A**.

### 1. Предварительные требования

| Инструмент | Минимальная версия | Зачем |
|---|---|---|
| **Docker** + **Docker Compose v2** | Docker 24+, Compose v2 | Поднимает весь стек одной командой |
| **Go** | 1.25 | Только для Способов B/C и запуска Go-тестов |
| **Node.js** + **npm** | Node 22+ | Только для запуска фронтенда вне Docker |
| **sqlc** | последняя | Только если меняете SQL-схему/запросы |
| **golangci-lint** | последняя | Только для линтинга |
| **curl** + **jq** | любые | Для smoke-теста и ручных проверок API |

Проверьте, что Docker запущен:

```bash
docker version
docker compose version
```

> ⚠️ **Сборка бэкенда требует CGO** (`CGO_ENABLED=1`): пакеты `confluent-kafka-go` (librdkafka) и `chai2010/webp` — cgo-зависимости. На хосте для Способов B/C нужны `gcc` и `libc6-dev`. В Docker это уже учтено в `Dockerfile`.

### 2. Карта портов и сервисов

Важно: внутри Docker-сети сервисы общаются по внутренним портам, а на **хост** некоторые порты проброшены с другими номерами, чтобы не конфликтовать с локальными установками.

| Сервис | Адрес для браузера/хоста | Внутренний адрес (Docker-сеть) |
|---|---|---|
| Фронтенд (Nuxt) | http://localhost:3000 | `frontend:3000` |
| Бэкенд REST/WS/SSE | http://localhost:8080 | `app:8080` |
| Сигналинг звонков | ws://localhost:8090 | `call:8090` |
| PostgreSQL | `localhost:5433` | `postgres:5432` |
| Redis | `localhost:6380` | `redis:6379` |
| Kafka | `localhost:9092` | `kafka:29092` |
| MinIO API | http://localhost:9100 | `minio:9000` |
| MinIO консоль | http://localhost:9101 | `minio:9001` |

> 🔑 Запомните: проброшенные на хост порты (Postgres `5433`, Redis `6380`, MinIO `9100`) отличаются от внутренних, чтобы не конфликтовать с локально установленными сервисами.

### 3. Запуск — всё в Docker

Поднимает бэкенд, сигналинг, фронтенд и всю инфраструктуру.

```bash
# 1. Скопировать пример окружения
cp .env.example .env

# 2. (опционально, но желательно) задать свой JWT_SECRET в .env
#    JWT_SECRET=<любая случайная строка 32+ символов>

# 3. Собрать и запустить весь стек
docker compose up -d --build
# либо короткая форма:
make up
```

Дождитесь, пока контейнеры станут healthy (бэкенд ждёт postgres/redis/kafka/minio):

```bash
docker compose ps
docker compose logs -f app      # логи бэкенда
```

Когда всё поднялось:

- Откройте клиент: **http://localhost:3000**
- Проверьте здоровье бэкенда: `curl http://localhost:8080/health`
- Консоль MinIO: **http://localhost:9101** (логин/пароль `minioadmin` / `minioadmin`)

Остановить стек:

```bash
docker compose down          # остановить, сохранив данные
docker compose down -v       # остановить и удалить тома (полный сброс БД)
make down                    # = docker compose down
make db-reset                # пересоздать тома и схему после изменения SQL
```

> ℹ️ Первый запуск долгий: собирается Go-бинарь с CGO, фронтенд ставит npm-зависимости (`npm install` внутри контейнера). Последующие запуски быстрее благодаря кэшу и тому `frontend_node_modules`.

### 4. Переменные окружения

Конфигурация читается из переменных окружения (`pkg/config/config.go`). Полный список с комментариями — в `.env.example`. Ключевые:

| Переменная | По умолчанию (хост) | Назначение |
|---|---|---|
| `ENV` | `development` | Режим окружения |
| `HTTP_PORT` | `:8080` | Порт REST/WS/SSE |
| `JWT_SECRET` | заглушка | **Обязательно** заменить в проде (32+ символов) |
| `POSTGRES_DSN` | `postgres://krampus:krampus_pass@localhost:5432/krampus?sslmode=disable` | Строка подключения к Postgres |
| `REDIS_ADDR` | `localhost:6379` | Адрес Redis |
| `KAFKA_BROKERS` | `localhost:9092` | Брокеры Kafka |
| `AWS_ENDPOINT` | `http://localhost:9000` | Эндпоинт MinIO/S3 |
| `STUN_SERVERS` | `stun:stun.l.google.com:19302` | STUN-серверы для WebRTC |
| `CALL_MAX_PEERS` | `8` | Предел участников звонка |

> В `docker-compose.yml` значения `POSTGRES_DSN`, `REDIS_ADDR`, `KAFKA_BROKERS` и `AWS_ENDPOINT` для контейнера `app` переопределяются на имена сервисов внутри сети — менять `.env` не нужно.
